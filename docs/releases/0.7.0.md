# 0.7.0 release

Status: released on 2026-10-30.

## Scope

- Render supported documents inside Paseo file tabs, using the existing viewer and its search, review and format-specific tools.
- Subscribe to file changes without reading the entire file through the host handle. Release subscriptions when a panel closes.
- Clear stale content after deletion or a symlink retarget, and recover when the file returns.
- Correct the Documents action and opening chooser to say Open full view for the standalone viewer.
- Require Paseo 0.13.0 on both the app and daemon, and typecheck against SDK 0.13.0.

Documents, turn cards and `/doc` retain their existing navigation. Opening a file tab from a plugin needs a public host navigation API; see [the proposal](../host-api-proposals.md#open-a-workspace-file-in-a-file-tab).

## Validation on 2026-10-30

- Typechecks pass, including the browser harness.
- Unit suite: 104 files pass, with 832 passing tests, one expected failure, two skipped tests and one todo. The source-checkout-only Paseo compiler checks are among the skipped tests.
- Browser component suite passes, including 390 px and 320 px file panels, light theme, no duplicate Documents navigation, file rewrites, deletion and restoration, symlink retargeting, review composer preservation, watcher cleanup, and no whole-file reads or file writes through the handle.
- The devkit's host check passes all 13 checks against the installed Paseo 0.14.0 compiler and evaluator, including client registration, icons, module boundaries and Hermes.
- `npm run test:host` passes 11 checks against a fresh, dedicated Paseo 0.14.0 daemon and its real web UI. It covers PDF, Word, Excel and PowerPoint file tabs, repeated opens, PDF download bytes, a note preserved across tab closure, the actual Viewer/Source picker, Open with and remembered associations, a fake-agent rewrite, deletion and restoration, the turn-ended timeline card, split panes and a chat link opening the compact file viewer in a dark theme.
- The host test tears down its daemon and removes its temporary workspace and plugin state on success or failure. It uses the published devkit SDK and does not target the regular daemon.
- Package dry run includes the file panel implementation and runtime dependencies.
- A fresh Git installation of commit `3895681` runs the manifest's production-only dependency build, reaches `running` and passes the app's client registration rules in the isolated daemon.

The [host report](../../verify/0.7.0/report.json) records no console or plugin evaluation errors. ## Tooling

Devkit 0.1.0 checked client registrations with Paseo 0.11 rules and failed `client-eval` on the file panel and context-free workspace panel. Devkit 0.2.0 checks against the Paseo version in use and passes all 13 checks against the installed 0.14.0 app. Against a Paseo build from between 0.13.0-beta.1 and beta.2 it correctly fails `client-eval`, because builds before beta.2 reject the context-free Documents panel.

## Coverage limits

Compact layout checks use the real web UI at a phone viewport. Physical iOS and Android devices, remote machines and relay connections have not been exercised for this candidate. The minimum SDK is 0.13.0; the installed app used for host verification is 0.14.0.

No release tag, GitHub release or registry update has been published. The dedicated test daemons are torn down after verification.
