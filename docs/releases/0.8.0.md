# 0.8.0 release verification

Local implementation on `feat/reader-ux-slide-notes`, tested with Paseo 0.15.3 on 2026-11-09. No release or registry update has been published.

## Changes

- Reader controls use 32 pt on wide desktop layouts, 28 pt in narrow desktop panels and 44 pt on phones.
- PowerPoint slide notes use an explicit slide unit, active slide index and file revision. They are text-only. Existing PDF drafts, pins, image attachments and revision warnings stay compatible.
- The note editor states that drafts stay on the device and are lost on app reload. The plugin retains its memory-only storage contract.

## Verification

- Typecheck passes.
- 834 unit tests pass, with one expected failure, two skipped checks and one todo.
- The full component browser suite passes, including 230/320 pt panels, phone layouts, themes and a slide note retained across a panel close/reopen, kept on its original revision after a rewrite removes its slide, and sent through the test agent interface.
- The installed Paseo 0.15.3 compiler, evaluator, Lucide checks and Hermes checks pass: 13 checks, no warnings or skips.
- The dedicated real-host suite passes 13 checks. It sends a text-only slide note to the credential-free fake agent, restores a file tab after browser reload, verifies file changes and panel associations, and checks the compact viewer at 390 px.
- Every test daemon, temporary workspace and plugin-state directory is removed in teardown. The regular Paseo daemon is not targeted.

The real-host suite used the local devkit build through `PASEO_DEVKIT_ENTRY=/path/to/paseo-plugin-devkit/dist/index.js`. The published 0.2 SDK remains supported; newer builds provide the extracted file-tab helpers.

Evidence: [host report](../../verify/0.8.0/report.json), [PowerPoint tab](../../verify/0.8.0/file-tab-slides.png), [slide review sent](../../verify/0.8.0/slide-review-sent.png), [compact viewer](../../verify/0.8.0/compact-file-view.png).

## Adversarial review

A real deck rewrite exposed an inaccessible unfinished note when its slide no longer existed. The reader now keeps the editor open across revisions and restores the original anchor after reopening, even if it is outside the new slide range. The browser regression checks the text, original slide number, stale warning and sent message.

## Limits

The real-host UI run uses the served web app; the native Electron window, iOS app and Android app were not driven. Reading-position persistence is unchanged. Spreadsheet-range notes, document excerpts and durable draft storage remain separate work.
